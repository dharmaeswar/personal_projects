# Data Governance & Privacy Platform

A local, end-to-end data-governance platform built in Python (standard
library only) — a portfolio project matching the charter of SoFi's
**Data Trust** organization and its "Senior Software Engineer, Data
Platform" role.

**All data is synthetic and seeded in code.** No real company or customer
data appears anywhere in this project, and nothing here was used in
production or by any real company.

## What it does

| Module | SoFi Data Trust charter item |
|---|---|
| `governance/catalog.py` | **Metadata architecture** — a registry of datasets with owner team, source system (Snowflake / S3 / Postgres), columns, retention window and legal-hold flag |
| `governance/classify.py` | **Data classification** — rule-based PII/sensitivity classifier (email, phone, SSN, person name, street address, account numbers, dates of birth) using column-name patterns plus sampled-value checks; every classification names the rule that fired |
| `governance/masking.py` | **Data masking for sensitive data in Snowflake** — redact, partial mask (last 4), deterministic SHA-256 hash, tokenize; restricted columns are never returned raw to non-privileged roles |
| `governance/access.py` | **Fine-grained least-privilege access (RBAC)** — roles (admin, data-engineer, analyst, auditor) plus purpose-based rules; includes an access-request log |
| `governance/retention.py` | **Data retention and legal-hold enforcement** — per-dataset actions (retain / delete-candidate / held); a legal hold blocks deletion entirely |
| `governance/erasure.py` | **CCPA/GDPR deletion and access automation** — erases a subject's records across all datasets, skips held datasets, and produces an audit report |
| `run_governance.py` | End-to-end demo + **affiliate boundary / GLBA-FCRA-style purpose controls** (e.g. support staff may not read restricted columns; model training is blocked on held data) and **pipeline observability** via the human- and machine-readable reports it writes |

The demo also seeds the catalog with realistic columns and a few planted
PII columns, so classification, access, retention and erasure all run
against the same data.

## How to run

```bash
pip install -r requirements.txt   # pytest only
python run_governance.py          # demo: writes governance_report.txt + governance_report.json
python -m pytest -q               # tests
```

Requires Python 3.12. The app code uses only the standard library, so it
runs anywhere with system Python.

## Demo results (real run)

Seeded catalog: **4 datasets** (`members`, `transactions`,
`loan_applications`, `support_tickets`) across Snowflake, Postgres and S3.

- **Classification:** 29 columns classified — 16 internal, 9 confidential,
  4 restricted. Planted PII found as expected: `ssn` and `account_number`
  restricted; `email`, `phone`, `full_name`, `date_of_birth`,
  `street_address`, `income`, `credit_score` confidential.
- **Access requests:** 8 evaluated — **4 allowed, 4 denied**.
  Denied: analyst reading `ssn` (restricted ceiling), model training on
  `loan_applications` (legal hold), support purpose reading
  `account_number` (purpose restriction), unknown role `intern`.
  Allowed: analyst reporting on `members`, auditor audit read (masked
  only), admin operations on `ssn`, analyst model training on
  `transactions`.
- **Retention:** `transactions` is a delete-candidate (age 800d >
  retention 730d); `loan_applications` is held (legal hold);
  `members` and `support_tickets` retained.
- **Erasure (CCPA/GDPR) for subject `SUBJ-1007`:** **4 records erased**
  (1 in `members`, 2 in `transactions`, 1 in `support_tickets`); the
  subject's 1 record in `loan_applications` was **kept under legal hold**
  and reported as held.
- **Tests:** **48 passed** (`python -m pytest -q`), including a
  determinism test — running the demo twice produces byte-identical
  reports.

## Layout

```
governance/
  catalog.py     # dataset registry (metadata architecture)
  classify.py    # PII / sensitivity classification
  masking.py     # redact / partial / hash / tokenize
  access.py      # RBAC + purpose-based access, access-request log
  retention.py   # retention windows + legal holds
  erasure.py     # CCPA/GDPR subject erasure + audit report
run_governance.py
tests/           # pytest suite (classify, masking, access, retention/erasure, demo)
governance_report.txt / .json   # generated by the demo run
```

## Honest limits

- This runs locally with in-memory tables, not a Snowflake instance —
  the catalog, masking and erasure logic is the real deliverable; the
  storage layer is a simulation.
- The classifier is rule-based (name patterns + value regexes), not an
  ML model; a plain `YYYY-MM-DD` value is deliberately **not** treated
  as a date of birth, because transaction dates share that shape
  (see `test_plain_date_column_is_not_a_dob`).
- Erasure deletes rows from the in-memory tables; a production erasure
  would issue DELETEs against Snowflake / Postgres and object deletes
  in S3, then verify with a re-scan.
