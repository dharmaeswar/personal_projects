FRAUD-DETECTION MODEL VALIDATION REPORT
Independent Model Validation — Model Validation Report (MVR) style
========================================================================

All data in this validation is synthetic and seeded. No real bank,
cardholder, or transaction data is used, and nothing here is a claim
about any real institution.

1. Scope
------------------------------------------------------------------------
Validate a card-transaction fraud-scoring model used to flag
transactions for review. Champion: logistic regression on scaled
features. Challenger: gradient boosting. Benchmark: base-rate
(overall fraud rate) predictor. Assessment covers outcomes
analysis, calibration, ongoing monitoring, and fairness slices.

2. Data
------------------------------------------------------------------------
Synthetic transactions: 20,000 total (16,000 train / 4,000 test).
Overall fraud rate: 1.70%. Features: amount, hour,
merchant category, device age, 1h/24h transaction velocity,
account age, cross-border flag, card-present flag. Segment:
region (North / South / East / West). RNG seed fixed at 42,
so the dataset is fully reproducible.

7. Limitations
------------------------------------------------------------------------
- Synthetic data: relationships are designed, not observed; real
  fraud patterns, seasonality, and adversarial adaptation are absent.
- No out-of-time test: train/test is a random split, so performance
  may overstate results on future transaction vintages.
- No cost model: the F1-tuned threshold ignores the asymmetric cost
  of a missed fraud vs a false alert.
- Fairness slices cover region only; other protected or sensitive
  attributes are not present in the synthetic data.

8. Required Actions
------------------------------------------------------------------------
1. Recalibrate the champion at the high-score tail before production use.
2. Re-validate on an out-of-time sample before the next model review.
3. Set the operating threshold from a cost analysis, not F1 alone,
   and document the chosen trade-off.
4. Put PSI and flag-rate-by-region monitoring on a monthly schedule,
   with alerts at PSI > 0.1 and a flag-rate gap review above 5pp.
5. Re-run the challenger comparison when at least one more month of
   production data is available.
