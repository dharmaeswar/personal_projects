# Inventory–Demand Allocation Simulator

A data-science project for the Stitch Fix — Data Scientist, Logistics Algorithms role
(Greenhouse 8406513). It answers the team's core question: how do we put the right
inventory in the right places at the right times, and prove the sourcing policy works?

**Demo project. Synthetic data only.** Nothing here contacts Stitch Fix, a real
retailer, or a real fulfillment network, and no production deployment, customer use,
or real shipment history is claimed. All demand, inventory, cost and lead-time numbers
are generated from a fixed seed for demonstration.

## What it does

1. **Forecast** (`inventory_ds/forecast.py`) — weekly demand per style–region.
   Two explainable models: statsmodels Holt-Winters exponential smoothing and a
   scikit-learn Ridge regression on lag, trend and seasonality features. The report
   compares MAPE on a holdout and shows the Ridge coefficients so a non-technical
   reader can see *why* the forecast moves.
2. **Allocate** (`inventory_ds/allocate.py`) — matches on-hand inventory to forecast
   demand. A greedy cost-aware pass, then a `scipy.optimize.linprog` refinement that
   minimises shipping cost plus a stockout penalty, subject to FC capacity and
   on-hand inventory. Reports fill rate, unmet demand and cost per policy.
3. **Simulate** (`inventory_ds/simulate.py`) — Monte Carlo fulfillment simulation.
   Demand is drawn from the forecast distribution (hundreds of replications) and each
   sourcing policy is scored on fill rate, stockouts and cost, with percentile bands.
4. **A/B test** (`inventory_ds/ab_test.py`) — analyses a simulated experiment of the
   two sourcing policies: two-proportion test on fill rate, Welch's t-test on cost
   per order, confidence intervals, minimum detectable effect and a go / no-go
   recommendation.
5. **Report** (`inventory_ds/report.py`, `run_analysis.py`) — runs the whole pipeline
   and writes charts (matplotlib) plus `report.md` under `output/`.

## Layout

- `inventory_ds/forecast.py` — Holt-Winters + Ridge demand forecasting, holdout MAPE.
- `inventory_ds/allocate.py` — greedy + LP allocation of inventory to forecast demand.
- `inventory_ds/simulate.py` — Monte Carlo fulfillment simulation across policies.
- `inventory_ds/ab_test.py` — A/B test statistics for the two sourcing policies.
- `inventory_ds/report.py` — charts and the markdown summary report.
- `inventory_ds/data_gen.py` — deterministic synthetic data generator (seeded).
- `run_analysis.py` — CLI entry point: generate data, forecast, allocate, simulate, A/B test, report.
- `data/` — generated demand history and inventory snapshot (regenerated by the run).
- `tests/` — pytest tests for every module.

## Run it

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python run_analysis.py
.venv/bin/python -m pytest -q
```

## Results (seeded run)

- Forecast holdout sMAPE: Holt-Winters 0.092, Ridge 0.075 (Ridge wins on 7 of 12
  style–region series; the report picks the better model per series).
- LP allocation fills the same 91.8% of forecast demand as the greedy nearest-FC pass
  (inventory is the binding constraint at 92% stock cover) but at lower cost:
  $9,032.80/week vs $10,091.80/week, $5.74 vs $6.41 per filled unit.
- Monte Carlo (500 replications): fill rate 90.3%–93.6% (5th–95th percentile) for
  both policies; the LP policy's cost band sits ~$1,050/week below greedy.
- A/B test (4,000 orders per arm): fill-rate lift +2.85 pp, 95% CI (1.66, 4.04),
  p = 3e-06; cost per order $0.59 lower, p < 0.001. Recommendation: GO.
